# SwasthaDisha priority test scenarios

**Draft 2, proposed design v1.7, 9 November 2026.** These 115 selected scenarios are the authoritative specification for this catalogue. They include25 concrete regressions from two supplied principal reviews. They are not an exhaustive test suite or passing application evidence; expand allowed/forbidden state, input, scope and failure interleavings from each module contract. Numeric fixtures are synthetic assertions, not production prices, legal thresholds or universal clinical SLAs.

## Fixtures and execution rules

Use synthetic businesses A/B, branches A1/A2, similar/shared-phone patients, separate payers/caregivers and active/revoked actors. Establish explicitly disposable replica-set DB, test-only identity/storage/provider stubs before any mutation/cleanup. A name containing test is insufficient; current scripts can connect before the name check, syncIndexes and dropDatabase, and an API smoke script can mutate an existing appointment. Do not run them against ordinary .env resources.

Freeze clocks, branch timezones, policy/quote/UOM versions and declared legacy versus target amount units. Current pharmacy availableQty already excludes reservedQty: do not subtract held stock twice. P0 means safety/security/money/stock/clinical integrity blocker for its own live workflow; future P0 scenarios do not become M0 dependencies. Each row has its actual gate. Catalogue/clinical/financial authority cannot be obtained through a generic body field.

Parameterize actor/object/field authority, tenant/branch, app/counter/phone/API origin, absent/null/unknown input, boundary/overflow, duplicate/reordered/delayed events, two-process contention, timeout and crash before/after irreversible boundaries, partial completion/reversal and restored replay. Use property/state-machine conservation checks as well as named examples. Expected assertions include DB fields, exact deltas/row counts, versions, preserved bytes, zero forbidden provider calls and reconciliation, not HTTP200 alone. Approved policy supplies genuine unresolved rules; do not invent clinical/legal/commercial approval from a fixture.

This file owns test steps. CSV owns status/evidence only. PASS requires the exact implementation/run/fixture/environment and assertions; BLOCKED means the check could not execute. Preserve historical missing-tsc BLOCKED even if an earlier separate run found source errors. Existing test names/stubs are partial candidates, not proof of these broader scenarios. Only the two previously recorded local commands have execution outcomes; new cases are NOT_RUN and three deliberate future cases remain DEFERRED.
