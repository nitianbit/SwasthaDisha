## Qualifications to the supplied amendments

- A1's independent reconciliation requirement is accepted. The phrase “nothing looks up payments” is too broad: `fetchRazorpayPayment` already runs during client verification. The missing independent intake/recovery is the defect.
- A2 preserves actual wallet credits, but a legacy `refunded` label alone cannot prove a wallet credit or gateway refund. Match wallet/provider evidence, preserve original records, and quarantine unresolved classifications.
- A3's blanket “honour any authorization before expiry” is bounded by availability and trusted timing. Claim/retain the allocation before gateway reconciliation/capture, make no network call inside a Mongo transaction, and never take capacity from another accepted order. Checkout timeout is not the provider's maximum possible late-authorization interval.
- A4 uses structural guards plus runtime deny and real tenant fixtures. Static analysis alone cannot prove every aggregate/filter is safe. Legacy scope migration must preserve explicit owned-resource checks now, not wait for all new modules.
- A5 retains every meaningful version while deduplicating identical deliveries. Completeness and release approval are separate states; scoped content hashes avoid cross-business lookup/dedup leakage. Corrections need current recipient/legal-basis policy, not indiscriminate resend after withdrawal.
