# Open source reuse options for Jansetu

Research date: **8 November 2026**. **35 distinct projects screened**, including exclusions because their current terms or maintenance do not fit. This is a bounded comparison, not an inventory of every public repository. No candidate was installed, executed, imported or merged. **100 RPS remains unverified.**

The integration baseline is Jansetu's Express 4, TypeScript 5.4, Mongoose 6.6, TypeDI/Joi, Razorpay, provider adapters and Mongo jobs. The [capability matrix](CAPABILITY_MATRIX.md) identifies existing pharmacy batches/reservations, retail/wholesale prices, connected counter orders, appointments and payments. The [business specification](BUSINESS_OPERATIONS.md) adds private daily operations for pharmacies, labs, clinics and hospitals, with optional marketplace listing. Labs may use APIs or a Jansetu panel; counter sales require connectivity initially; hospital OPD/billing precede advanced HMS.

Detailed [clinical](oss-research/clinical-notes.md), [commerce](oss-research/commerce-notes.md), [platform](oss-research/platform-notes.md) and [supplementary](oss-research/supplementary-notes.md) notes contain inspected source URLs, metadata snapshots and unresolved checks. See the [method](oss-research/METHOD.md), [citation registry](oss-research/CITATION_REGISTRY.md) and [counter-review](oss-research/counter-review.md). Upstream features below are documented claims, not proof they exist in Jansetu or satisfy its acceptance criteria.

## Recommended decision

**Keep this backend. Trial small reusable components first:** CASL for server permissions; Refine Core for the missing business panels if the frontend team chooses React, with react-admin as the alternative; k6 as a separate verification tool. Compare hardening Mongo jobs against BullMQ before replacing the queue. These supply primitives rather than completed business modules. The table below links their actual license and integration evidence.

**Evaluate ERPNext plus Marley as one separate business/clinical stack** when substantial purchasing, stock, accounting and OPD requirements justify it. InvenTree is a narrower supplies alternative; Odoo Community is the alternative ERP. **Evaluate OpenELIS Global for advanced lab operations**, while small labs without APIs can use a native Jansetu panel. API absence alone does not require a full LIS.

These are engineering recommendations with **medium confidence** until trials pass. No full application has sufficient evidence for an immediate whole-repository merge. A matching language or database does not establish compatible models, permissions, licenses or transactions. Conversely, an exact-fit hospital/lab system could save considerable workflow work. Compare those savings with adapters, extra databases, reconciliation, migration, training and upgrades. Use the roadmap's post-M0 planning windows and re-estimate M0 at kickoff; no reuse-related schedule saving is assumed before evidence.

## What reuse still leaves us to build

This is proposed Jansetu architecture, not an upstream capability claim. Fewer authorities make failures easier to reconcile.

| Record | Authority rule |
| --- | --- |
| Business/staff/publication | Jansetu membership, branch access, private operations and optional listing; explicit external tenant mapping. For Frappe, decide site-per-business versus a shared-site/company design and prove both isolation and operating cost; company labels are insufficient |
| Patient/care | Stable Jansetu patient identity; external patient/encounter/specimen mapping; deliberate clinical authority, consent and amendment history |
| Stock | One writer per store/balance. If ERP owns it, all channels reserve/consume there; Mongo holds a projection. Otherwise export records and prevent competing stock writes |
| Lab/order | One commercial order contract for API and panel partners; source attribution, assignment, sample/report states and correction versions; explicit LIS accession mapping |
| Money | Distinct invoice, receipt, attempt, refund, credit, commission, subscription fee and payout records; name the invoice issuer and payment/refund/ledger owner for each flow, map immutable references and reconcile. Gateway collection is not proof of vendor payout |
| Files/events | Private access, file validation, signoff, corrected reports, authenticated events, durable delivery/replay and recovery; queue adoption supplies none of these policies automatically |

## Trial order and pass/fail gates

1. **Foundation first.** Resolve documented clean-install/build, access, file and webhook blockers. Pin a supported runtime. Use an isolated development branch with synthetic data. No production migration is authorized by this research.
2. **CASL plus one panel slice.** Two businesses/two branches; receptionist, clinician, technician, signatory and vendor roles. Show lab inbox, sample action, report upload/finalize/private download in Refine. Compare react-admin if needed. Pass negative list/detail/write/export/file tests, build compatibility and save-failure recovery; record actual custom code and paid-feature needs.
3. **Queue recovery comparison.** Same outbox/job contract on hardened Mongo and selected BullMQ release/backend. Kill workers near side effects, replay duplicates, time out providers and restore stores. Require recoverable observable attempts, fast API acknowledgement and no duplicate financial mutation; choose one queue after measuring operating cost.
4. **One business-engine trial.** ERPNext/Marley versus native completion; InvenTree if supplies-only, Odoo as alternative ERP. Replay partial purchase receipt, box/strip/tablet conversion/rounding, two expiry batches, expired/quarantined exclusion, simultaneous app/counter last-unit sale, branch transfer, wholesale price snapshot, original-batch partial return, supplier return, credit/refund and consumable wastage reversal. Require isolated second business and reconciled totals.
5. **Advanced lab only when warranted.** OpenELIS order/patient mapping, accession, rejection/recollection, reviewer approval, corrected report, private retrieval and consumable effect. Prove actual event authentication, replay and outage handling. Otherwise ship the bounded native panel.
6. **Provenance/migration/load.** Pin commits, licenses/exceptions/notices and complete dependency inventory; review intended distribution/network model; prove exports, upgrade/rollback and restore. Then measure released workload at 100 HTTP RPS including actual external authorities/failure cases and zero integrity violations. No schedule savings before evidence.

## Key disputes and limits

- **Workflow breadth versus operating cost:** established ERP/LIS could save development; adapters, upgrades and reconciliation may outweigh that. Compare the same bounded flow against native completion.
- **Public source versus permission:** copyleft, Enterprise and source-available terms differ. Root badges are incomplete. Separate deployment or porting to TypeScript does not erase provenance or automatically settle obligations.
- **Activity versus suitability:** a push may be a translation/profile change. HospitalRun is archived; SENAITE is active with a documented legacy-runtime constraint. Stars and recent commits are not security evidence.
- **Docs versus selected release:** BullMQ PostgreSQL, ERPNext development requirements, Odoo edition/version and Cal.com's public/private split change selection. Inspect the actual version before implementation.

This research did not audit every dependency, certify legal/regulatory fit, run deployments or rehearse migrations. GNU Health current-source license, uniCenta archive/API terms, IDURAR license metadata and selected-release compatibility remain open. Application implementation and any source import require a scoped follow-up task. Preserve the existing security and 100 RPS acceptance gates.
