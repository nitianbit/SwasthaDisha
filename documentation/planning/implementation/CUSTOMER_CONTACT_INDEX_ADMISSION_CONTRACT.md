## Exact observation and safe data boundary

The fixed observation has these exact top-level fields:

`schema, mode, binding, status, collectionSpec, indexes, completion, failure`.

- `schema`: `SD-USER-CONTACT-INDEX-OBSERVATION-1`; `mode`: the manifest's exact mode.
- `binding`: exact `{ databaseName, collectionName, namespace, collectionUuid }`, with nonempty bounded database name, collectionName exactly `users`, namespace exactly databaseName + `.users`, and actual acquired UUID as32 lowercase hex. An absent/unestablished binding is null in a failed observation.
- `status`: `COMPLETE`, `INCOMPLETE`, `FAILED` or `UNSUPPORTED`. A prefix, unsupported row, limit, unknown reply/cleanup or timeout is never COMPLETE.
- `collectionSpec`: full supported owned data clone of the one authoritative listCollections row, or null before acquisition. Exact row keys are `name,type,options,info,idIndex`; name `users`, type `collection`, info exactly `readOnly:false` plus acquired UUID; idIndex is the actual ordinary ID spec. Initial options permit only an absent/explicit collation object; unsupported options/views/timeseries/clustered forms deny rather than being filtered away. The raw options record is retained even when empty: absent collation in an observed complete options record establishes simple default; a missing record establishes nothing.
- `indexes`: every acquired wrapped row, in acquisition order. Successful rows are exactly `{ spec: SafeIndexSpec }`. No name/key filtering, sorting, coalescing or replacement of a row by a declared schema index. Failure may retain a bounded prefix for diagnosis, but its status remains noncomplete.
- `completion`: exact `{ indexRows, logicalMetadataBytes, commandCount, elapsedMs, collectionCursorExhausted, indexCursorExhausted, sessionEnded, cleanupConfirmed }`; counts are safe nonnegative integers, elapsedMs finite nonnegative. Every exhaustion/session/cleanup flag must be true for COMPLETE. There must be no still-pending command/promise when COMPLETE is returned.
- `failure`: null only for COMPLETE, otherwise one fixed code below. No driver message, query, URI, client object, credentials or patient record is returned/logged.

The reader validates native BSON results through own data descriptors before copying; reject proxies before reflection using stdlib `util.types.isProxy`, accessors, symbols, cycles, functions and unsupported prototypes/types. Permit only plain/null-prototype objects, dense plain arrays, finite numbers, booleans, bounded strings/null, and the pinned driver's actual Long/Binary/Timestamp forms at their declared transport/UUID/cursor positions. Use the pinned native class prototype operations, never a supplied `toJSON`, `toBSON` or overridden method. Copy accepted buffers/data; do not retain mutable server result references. UUID is copied to the fixed hex representation; signed64 cursor IDs are kept as actual native Long values privately and represented as canonical decimal strings only for validation/diagnosis. Never pass cursor IDs through Number.

Pure evaluation sees only the owned plain-data representation and uses descriptor inspection, a maximum8192 nodes, depth16 and the shared262144-byte budget; it repeats closed-shape/type validation and does not invoke getters/string coercion. Native/BSON client identity cannot be proved from a JSON observation; only actual reader/fixture evidence establishes acquisition provenance.

`logicalMetadataBytes` is the cumulative BSON logical size of each fully inspected raw command reply, computed with the already-installed driver's BSON size routine on a descriptor-validated owned BSON copy, plus its safe serialized observation size where larger. Reject a reply/clone before further allocation when the accumulated bound is exceeded. Transport framing/compression are not this measurement. The driver necessarily receives/decodes a reply before this application check:262144 is an admitted metadata/retention bound, **not** a claimed network-frame or pre-decoder heap cap. The isolated fixture has separate process/output/memory caps. Unknown fields are retained only until rejection; they cannot disappear into a fabricated COMPLETE result.

## Fixed acquisition, cursors and collection generation

Only these explicit native Db commands are admitted by the future reader profile, all on that captured Db/session, primary read preference, promoteLongs false, promoteBuffers false and UTF-8 validation enabled. Command literals/options are constructed internally; no caller spreads, dbName/authdb overrides or SDK listIndexes helper that silently omits includeIndexBuildInfo.

1. `listCollections:1`, filter exactly `{name:'users'}`, nameOnly false, authorizedCollections false, cursor batchSize2 and server maxTimeMS at most500. Validate an `ok:1` reply and cursor envelope. For this exact-name ordinary collection, require exactly one full row and terminal zero cursor. Zero rows means collection unavailable; multiple rows, wrong name/type/options/UUID or nonterminal/foreign namespace deny. Expected cursor namespace is captured database + `.$cmd.listCollections`; cleanup may use only its captured valid namespace/ID. Do not treat an authorization error as empty options/default simple.
2. `listIndexes` targets the **actual UUID** copied from that row, with includeIndexBuildInfo true, includeBuildUUIDs absent, cursor batchSize16 and maxTimeMS at most500. A dropped/recreated same-name collection must not switch this read to another UUID. Require reply cursor namespace exactly the captured database + `.users`.
3. If its cursor is nonzero, issue only `getMore` with the held native Long ID, collection `users`, batchSize `min(16,65-rowsSeen)`, the same Db/client/session and no maxAwaitTimeMS. A non-tailable metadata getMore gets no invented server maxTimeMS/AbortSignal guarantee. Every continuation must retain the exact namespace and same nonzero ID or become zero; unexpected identity, malformed batch or a nonterminal empty batch gives INCOMPLETE. Maximum four getMore calls; a65th index row immediately exceeds the bound. At64 rows with nonzero ID, the final one-row getMore can prove zero/empty exhaustion or expose the65th row. Never mark a page prefix complete or rely on firstBatch length.
4. Recheck model/Db/client/session binding and UUID-bound namespace before acceptance. All index rows, including `_id_`, `name_text` and unrelated rows, remain in the observation. No collection-data reads or writes, index/collection create/drop/sync/rebuild, data repair/backfill, provider or application-start command occurs.

Each reply must be a descriptor-validated ordinary response. Its allowed outer fields are `ok,cursor,operationTime,$clusterTime`; cursor has only `id,ns,firstBatch` initially or `id,ns,nextBatch` on continuation. Native transport timestamps/signature metadata may be structurally copied for byte accounting but are not application authority. Reject missing/extra batch form, wrong primitive types, unexpected fields or an error reply; never fabricate zero cursor. Retain only IDs actually returned under the verified binding; a wrong namespace/unknown ID is not permission to kill some other cursor.

Mongo8's versioned command implementation accepts includeIndexBuildInfo and namespace-or-UUID targeting; completed specs are wrapped and in-progress information is explicit. These facts exist in8.0.0; no8.2 prerequisite is invented. [Mongo8 command source](https://raw.githubusercontent.com/mongodb/mongo/r8.0.0/src/mongo/db/commands/list_indexes.cpp), [Mongo8 catalog wrapping](https://raw.githubusercontent.com/mongodb/mongo/r8.0.0/src/mongo/db/catalog/list_indexes.cpp). ## Deadline and exact cleanup

Use a monotonic clock from the first binding check. The total acceptance window is5000ms including session/cursor cleanup. Stop ordinary acquisition by4000ms, reserve the final1000ms for cleanup, and do not start another acquisition command with less than1000ms before that cutoff. Check the remaining budget before/after every reply and while bounded-copying/evaluating. At most six acquisition commands are possible (one listCollections, one listIndexes, four getMores), all serial and awaited. There is no automatic retry.

For a known valid nonzero cursor, finally issue at most one `killCursors` on its exact captured pseudo/real collection with the exact held Long ID and same session, only while the remaining cleanup budget admits it. Require terminal killed/not-found confirmation without unknown/alive IDs, then end the owned session. A naturally exhausted cursor needs no kill. A drifted/unknown binding or exhausted deadline forbids guessing another cleanup target. Report CLEANUP_UNCONFIRMED and leave the separate owner-controlled fixture teardown to remove its own resources; do not clear the shared client/pool or adopt resources by names.

The driver4 options and monotonic checks bound a *successful admission*; they are not a cancellable socket API or a hard real-time promise. `Promise.race` alone never proves cancellation. A command still pending at the deadline cannot yield COMPLETE, and a late result cannot resume acquisition or turn failure into readiness. The separately reviewed diagnostic launcher must enforce the five-second owned metadata-child deadline and prove child/group, cursor/client and container cleanup under its actual ownership, including a hung-command case. It may close only its own admitted fixture client/process after source observation fails. There is no permission here to close an operational/shared client. If the admitted fixture cannot demonstrate that lifecycle, actual reader acceptance stays blocked rather than claiming a bounded pass.

## Supported index specs and exact readiness

Reject non-plain/getter/symbol/malformed data before field matching. Name uniqueness is global; different names sharing a key pattern are not automatically invalid. A row or its spec containing `indexBuildInfo`/`buildUUID` is unready by presence, regardless of marker truthiness; never erase a marker and accept its spec.

For ordinary numeric specs, supported fields are `v,key,name,ns,unique,sparse,hidden,background,expireAfterSeconds,partialFilterExpression,collation`. v is1 or2; key is a nonempty ordered plain map of at most16 bounded field names with only1/-1 values; name is1..256 non-NUL characters; optional ns must equal the held namespace. Boolean fields must be actual booleans; TTL if present is a nonnegative safe integer at most2147483647. Partial-filter data is preserved as bounded plain JSON (depth6); it is not executed or assumed equivalent by operator rewriting. Unknown option/type denies. Supported collation fields are `locale,caseLevel,caseFirst,strength,numericOrdering,alternate,maxVariable,normalization,backwards,version` with Mongo-valid scalar types/ranges; only locale simple with no conflicting options establishes explicit simple. A supported non-simple irrelevant index can remain observed without satisfying the required contact constraint.

The only supported text form is the retained `name_text`: ordered key `{_fts:'text',_ftsx:1}`, weights exactly `{name:1}`, textIndexVersion3, default_language absent or english, language_override absent or language. Its remaining supported fields are v/key/name/ns plus structurally valid ordinary boolean/background and collation metadata; TTL/partial/unique/sparse/hidden true or other text-specific/unknown forms deny. It must remain in the complete listing and cannot satisfy the contact requirement. Missing `name_text` is not repaired or silently replaced by schema declarations; it fails this initial retained-User profile.

Require exactly one completed `_id_` ordinary key `{_id:1}` with unique absent/true, sparse/hidden false or absent and no TTL/partial/build markers. Implicit uniqueness is accepted only for this exact ID index. The authoritative collectionSpec.idIndex must agree with it.

Require exactly one index named `user_contact_keys_v1` with ordered key `{contactKeys:1}`, unique true, sparse/hidden absent or false, no TTL/build markers, and exact partial structure `{contactKeys:{$type:'array'}}`. A differently named equivalent index fails. Candidate effective collation is simple only if explicit simple, or if absent and the fully observed collection options establish simple default. Missing collection options cannot establish default; non-simple default cannot make an absent candidate collation simple. A structurally supported non-simple default with an explicit simple candidate remains metadata-compatible. No text, array-of-key, alternate partial predicate, extra key, prepareUnique or hidden/building substitute.

## Result/error order and authority separation

Fixed codes: READY, MANIFEST_INVALID, OBSERVATION_INVALID, BINDING_UNAVAILABLE, UNSUPPORTED_PROFILE, COLLECTION_UNAVAILABLE, CURSOR_INCOMPLETE, INDEX_BUILDING, INDEX_UNSATISFIED, COLLATION_UNSATISFIED, LIMIT_EXCEEDED, DEADLINE_EXCEEDED, OBSERVATION_FAILED and CLEANUP_UNCONFIRMED. Validate manifest first, then observation shape/budgets/binding, acquisition status/completion/cleanup, supported full row structure/build state, ID/text retained profile, named contact requirement and effective collation. Only READY sets metadataReady true. Reader failures map to the corresponding fixed observation code with metadataReady false; unrelated driver errors are never reported as missing/ready. Full contact services map nonready admission to their existing503 CONTACT_IDENTITY_NOT_READY, without exposing metadata or another account.

Metadata readiness means only that this observed catalog constraint is suitable at this point. It is not all-account key coverage, old-writer shutdown, completed migration, current contact ownership, account-generation proof, rollout approval or an everlasting index lease. A separate reviewed maintenance/dry-run/backfill/cutover record must bind canonical/deduplicated keys for every legacy User row, resolve duplicates without automatic merge/reassignment, stop/drain old identity writers and prove every admitted signup/admin/HR/pharmacy/email/corporate writer uses the reviewed identity API. New customer signup's one-contact rule and legacy unverified-pair handling belong to the contact contract, not this metadata reader. No ambient/request boolean or new runtime registry can assert those facts. The eventual source composition requires both actual metadata admission and independently bound coverage/cutover admission; neither is manufactured by this document.

## Focused checks to freeze before execution

Pure evaluator checks run the **complete actual compiled new manifest/evaluator modules** against fixed supplied observations under the existing closed, dependency-free/pure admission. They do not execute a copied algorithm. Positive cases include every existing numeric index, retained text row, named correct contact partial index, zero/explicit-false equivalent options and actual complete collection-default evidence. Negative cases independently cover wrong name/key/order/unique/partial/TTL/hidden/build state, duplicate names, legitimate equal keys under distinct names, wrong/missing collection/UUID/ns/default collation, absent text/ID, malformed types/prototypes/descriptors/proxies/cycles, all row/byte/depth/deadline limits, and a nonterminal prefix. Non-simple default with absent candidate collation denies; explicit simple candidate with a fully observed non-simple default tests the stated rule. Required empty/skipped/TODO cases cannot pass.

Compiled whole-reader recording-port checks must use a fixed test-only module loader substituting only its known UserModel/Mongoose-native dependencies/clock; production reader gains no optional executor/URI override. Assert command literals/order, exact same-client session, UUID target, preserved rows, getMore namespace/Long identity, upper bounds, no follow-up after exhaustion/failure/deadline, exact cleanup scope, no caller options and zero DDL/data/provider effects. These prove the substituted boundary only.

A separate C3 recipe must pre-admit one exact synthetic fixture database/client/User model closure before import, disabled autoCreate/autoIndex before model compilation, fixed dependency lock/emit plan and no app/config/queues/provider imports. It installs its *own synthetic* User collection, ordinary/text indexes and named contact index through a separately reviewed create-only fixture setup, then invokes this actual reader. Capture all raw reply shapes, logical bytes, native Db/client/session and UUID identity, complete/exhausted cursors and exact cleanup. Force multiple actual batches; missing/wrong/hidden/in-progress metadata, read errors, namespace/UUID drop-recreate races, >64 rows, >256KiB metadata, deadline/hung getMore and unknown cleanup must fail without filtered completeness. Real-source controls removing name/partial/build/namespace/cursor/deadline checks must fail their actual focused assertions.
