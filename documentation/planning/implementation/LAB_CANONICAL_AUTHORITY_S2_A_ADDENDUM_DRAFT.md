## One useful source increment

Implement a protected **local callable operator**, `provisionLabAuthority(commandJson: string): Promise<LabAuthorityReceipt>`, that verifies one externally pinned issuer signature and creates a genuine canonical lab/organization/branches, then grants or revokes one named individual's operational membership using real same-client transactions. A valid admitted synthetic operator journey must persist real rows through this writer, not seed its nominal decisions directly. No CLI auto-execution, new HTTP route, login, admin JWT exception, new staff userType, professional qualification or patient access. Default imports create no connection, indexes, root, evidence, users or grants.

Exactly three action literals: `map_lab`, `grant_lab_reader`, `revoke_lab_reader`. Mapping is CREATE ONLY. No business/branch state update, source remapping, assignment, report, worklist, provider or money action is included. A suspended/revoked/expired business cannot be reactivated by regranting staff. Required administrative lab/branch lifecycle and key rotation/re-authorization remain subsequent source contracts **before real operational activation**. The existing pharmacy resolver, read port and minted-scope service are unchanged; existing lab authority still denies until S2-B. This is preparatory S2-A, never full S2/L2 or customer/pharmacy/lab completion.

The single pinned offline Ed25519 issuer replaces the broader draft's proposed two-key ceremony **only for this proposed phase**. One external protected key root avoids circular self-granting; two-key governance would add a new ceremony not required by the existing design. An OS-only local command cannot by itself bind a persisted issuer identity/action. No human independence, MFA, identity verification, production key custody or clinical approval is inferred from a valid signature. `issuerUserId !== subjectActorId` is mandatory for both membership actions. Security/owner acceptance of the real trust installation and protected writer exclusion remains required.

## Closed representations and canonical command bytes

IDs are lowercase24hex strings; digests lowercase64hex; revisions/fences positive safe integers, with expected revision0 only for a missing row. Times are nonnegative integer UTC epoch milliseconds <=8640000000000000, converted to validated Dates only at persistence. `now` is trusted server Date.now captured once PER transaction callback. Reject negative zero, NaN, infinity, unsafe numbers, null/undefined, coercion, proxies, accessors, symbols, sparse/extra-property arrays and unknown fields. Canonical string legalName is NFC/trimmed1..160 Unicode code points; registrationReference is NFC/trimmed1..128; neither admits controls. IDs/reason/action/keys use ASCII grammars, no URLs. No input normalization repairs a signed field.

`commandJson` is UTF8 text <=16384 bytes, no BOM/trailing newline/whitespace; depth<=8 and <=512 total values. Parse only bounded text. The complete parsed tree is arrays plus strings/finite integers, no objects or booleans except literal schema version integers. Require exact array arities, dense own enumerable data entries and `JSON.stringify(parsed) === commandJson`. This rejects duplicate object keys by forbidding objects and alternate escapes/numbers/ordering. Never call supplied conversion methods.

Let `B` be the following exact ordered array and let `S` be canonical padded base64 for exactly64 signature bytes. The entire envelope is `[B,S]` (arity2). The signed bytes are **only UTF8(JSON.stringify(B))**, no prefix/newline/BOM/hash-as-message. Ed25519 verify uses algorithm null with the fixed root's actual Ed25519 SPKI key; canonical base64 decode/re-encode equality required. `commandSha256` is SHA256 of those signed bytes, not envelope/signature bytes.

`B = ["sd.lab.authority.command",1,authorityGeneration,keyId,issuerUserId,organizationId,operationId,decisionId,submittedAt,notAfter,action,P]` (arity12).

`submittedAt <= now < notAfter <= submittedAt+900000`; root validity covers the entire signed window. The signed time is the stored `decidedAt`. Actual createdAt/updatedAt use callback now and satisfy decidedAt<=createdAt. Stable IDs/signature/input are reused unchanged across DB transaction callback retries; never sign inside a callback. All actions bind exactly one evidence ID+digest. Signature bytes themselves are not used for replay identity, so a second valid signature over identical signed bytes cannot manufacture a conflict.

Action payloads, exact order/arity:

- map_lab: `P=[labId,0,0,legalName,registrationReference,verificationValidFrom,verificationExpiresAt,evidenceVersionId,evidenceSha256,branchIds,"initial_mapping"]` (11). The two zeroes are expected lab and organization revisions. `branchIds` is1..100 strictly increasing unique canonical IDs. Require labId!=organizationId; every branch is explicitly covered by root scope; verificationValidFrom<=now<verificationExpiresAt, verificationExpiresAt<=root.expiresAt.
- grant_lab_reader: `P=[subjectActorId,membershipId,expectedMembershipRevision,expectedOperationalFence,branchId,validFrom,expiresAt,evidenceVersionId,evidenceSha256,"operational_assignment"]` (10). Missing membership requires expectedRevision0; existing membership must be revoked with that exact ID/revision. Active/suspended membership replacement409; use revoke then explicit regrant. `validFrom<=now<expiresAt<=min(lab.verificationExpiresAt,root.expiresAt)`. Exactly one explicit branch and `lab.worklist.read` grant; no submitted capability/role/grantDecisionId.
- revoke_lab_reader: `P=[subjectActorId,membershipId,expectedMembershipRevision,expectedOperationalFence,evidenceVersionId,evidenceSha256,"access_withdrawn"]` (7). Existing active or suspended exact membership only; already-revoked new operation409. Retain its single original reader grant/validity for history, change state to revoked and revision+1. Expired lab/membership or missing/inactive subject must NOT prevent authorized revocation; canonical identity/mapping/branch structure and issuer/root/metadata still required. No current subject read is needed for revocation. Issuer remains current active personal User, non-self, exact root scope.

No arbitrary reason text or optional/null payload positions. Unknown action/capability/arity denies before database lookup/effect. Supplied target IDs are desired scope only, verified against the signed root and actual current rows.
