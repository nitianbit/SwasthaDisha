## Frozen identity and normalized data

All IDs from an HTTP actor/route are primitive exact24hex strings without trim/coercion; canonical storage is lowercase24hex. Source-generated ObjectIds are not accepted as caller-selected asset/version IDs. In the first increment actor kind is exactly `user`; authenticated admin/HR/pharmacy/specialist callers are403 `DOCUMENT_ACTOR_FORBIDDEN`, not new clinical staff. The central authenticate401 retains precedence. Actor identity is a signed account ID, never a phone/email, corporate or linked business ID.

A trusted scope resolver returns exactly `{resourceKind, resourceId, ownerUserId}`. Kinds are `unbound_upload|booking|external_booking`. For unbound, resourceId=ownerUserId=signed user ID. For booking/external_booking, perform an exact scoped repository query with literal ID and mandatory scalar stored userId equality; absent/foreign404 `DOCUMENT_NOT_FOUND`. No optional owner, raw-filter spread, current userId hints, dependent ID or URL reference grants access. Resource authority must be read from the matching current stored row. The first increment does not expose a general client-supplied purpose/owner/source interface.

Stable logical asset identity is SHA256 of UTF8 JSON.stringify of this ordered ARRAY, without whitespace: `["sd-file-asset:v1", resourceKind, resourceId, ownerUserId, sourceSystem, sourceDocumentReference]`. sourceSystem enum is `owned_upload|labstack|healthians|legacy_import`. The tuple is stored alongside its lowercase64hex identityKey and compared on every collision; the hash alone is never authorization. The stable server-derived candidate assetId is ObjectId(identityKey.slice(0,24)), so concurrent first observations resolve the same asset before any version write. A prefix collision with a different FULL stored identity is409, never an ownerless adoption or regenerated second asset. This predictable identifier is not an access token; only the generated32byte storage filename is a secret object locator. Inside the capture transaction, insert the new revision0 asset if absent or compare the complete existing tuple; the unique identity/_id race aborts before the bounded fresh reconciliation transaction. Different loser version files remain private unreachable orphans. No separately committed asset reservation or undocumented audit phase is needed. For owned upload sourceDocumentReference is the caller's UUIDv4 documentKey (canonical lowercase UUID) scoped by current owner/resource. It names a logical document, not an asset ID or storage filename. One UUID per file; exactly one file/request in this increment. Retrying the same logical documentKey MUST resolve the same asset before version dedupe. A different documentKey means a different logical asset, even if bytes match.

Provider/legacy references are reserved internal source values only: bounded1–256 UTF8 bytes, exact nonempty strings with no C0/DEL or leading/trailing whitespace. Preserve opaque case and Unicode bytes; no lowercasing, trimming or NFC folding of provider identifiers. Unknown reference is not fabricated as a global common value: acquisition is503 until its source adapter can supply a stable reference. Provider account/integration namespace must be included in the future provider sourceDocumentReference contract; current enums alone do not establish provider-account scope. Those live adapters are excluded from the first increment.

`FileAsset` fields: schemaVersion1; server _id; exact stored identity tuple/identityKey; purpose `private_attachment|clinical_document|public_image`; resourceKind/resourceId/ownerUserId; server createdByUserId/createdAt; integer revision>=0; currentCapturedVersionId|null; currentReadableVersionId|null; revokedAt|null. Purpose is assigned by the service command: unbound upload→private_attachment; owned booking upload→clinical_document. Purpose and identity are immutable. Public_image is RESERVED, rejected by the first-increment public/HTTP/service commands; no current arbitrary imageUrl/profilePictureUrl promotes assets. Assets whose resource now resolves to a different owner deny503 `DOCUMENT_SCOPE_CHANGED`; do not reassign their owner or grant the new account the old bytes automatically.

`FileAssetVersion` immutable capture fields: server _id=versionId; assetId; identityKey; storageKey; contentSha256; actualSize(1..10MiB); mediaType enum PDF/JPEG/PNG/WebP; sourceSystem/sourceDocumentReference copied from asset; sourceVersionLabel `{kind:"unknown"}` or `{kind:"recorded",value:string}`; sourceStageLabel with the same tagged form; completeness `preliminary|final|unknown`; amendsVersionId|null; amendmentReason|null; capturedAt/createdByUserId assigned on FIRST successful capture. No clinical completeness/label/correction fields are accepted from first-increment HTTP uploads: they use unknown/unknown/unknown/null/null. Corrections with an explicit previous version are future qualified source adapters.

Server-generated versionId/storageKey/capturedAt/createdByUserId belong to the winning FIRST observation and are not compared to a freshly generated retry value or overwritten on retry. Current caller authorization is checked independently on each retry. Identical bytes with changed source stage/completeness/correction may be a new version; no dedupe by filename or hash alone.

Create-only correctness indexes: FileAsset `{identityKey:1}` UNIQUE; FileAssetVersion `{assetId:1,versionKey:1}` UNIQUE; FileAssetVersion `{assetId:1,_id:-1}` for listing; FileDocumentAudit `{operationId:1,phase:1}` UNIQUE. ## Transaction, pointer, audit and detach ownership

FileDocumentService owns its Mongo session using the same concrete model connection for asset, version and audit repositories. Do not accept req.session, caller raw filters, foreign client sessions or a fake default transaction. Expose no raw session parameter publicly. The repository's internal session capability is created per command and used for every related write; source/runtime evidence must prove one connection/session and transaction lifecycle. Session closes in finally. Driver errors propagate to the classified boundary; no catch-as-success or fallback writes. A duplicate-key race aborts that transaction; only after abort may a fresh bounded transaction read/reconcile the exact winning identity. Do not continue reads in an aborted session.

Allocate logical identity, operationId, candidate versionId/storageKey/capturedAt ONCE before withTransaction so callback retry does not create new identities/bytes. New asset revision0 is inserted with null pointers; capture transaction inserts/reuses version and sets currentCapturedVersionId using exact `_id,owner,identityKey,revision,revokedAt:null` predicate, incrementing revision once; create/retry compares the full tuple. Pointer updates return exact result and failure throws409 INSIDE the callback. CurrentReadableVersionId stays null for new quarantine. Validation of private_attachment can set it to that version in the same conditional transaction; clinical release can set it only after eligible validated publication. Old version bytes/capture fields never change. Duplicate successful upload reuses existing version/pointers and returns200 without incrementing or making an older retry the newest pointer. Operation replay does not duplicate transition audit. A rejected/unavailable scan creates no readable pointer.

Audit schema is closed `{operationId,phase,actorUserId,resourceKind,resourceId,assetId,versionId,outcome,createdAt,correlationId,byteCount}` (versionId is nullable; byteCount is null except a read_finished nonnegative safe integer bounded10MiB) with server-assigned bounded values; phase enum capture|validation|release|read_admitted|read_finished|revoke. Outcome enum captured|validated|rejected|released|admitted|completed|disconnected|failed|revoked; only the matching phase/outcome pairs are admitted. operationId collision/replay compares actor/resource/asset/version/phase and the original immutable result before reuse; a foreign operation ID409 never exposes another owner's receipt. No patient payload, hash, file URL, raw error or source credential. Mutating domain/audit records commit in the SAME Mongo transaction. Audit failure aborts the mutation; private orphan files may remain unreachable. Read admission rechecks current scope/state, records durable read_admitted BEFORE opening/releasing bytes, and fails503 if that write fails. read_finished records completed|disconnected|failed plus bounded server byte count after streaming; a post-byte failure cannot retract delivery, so read_admitted remains incomplete and failure is recorded as unresolved by the existing sanitized error boundary. Never report zero exposure when bytes already streamed. No long database transaction spans an HTTP stream, and no operational log can replace a required durable admission event.

Revoke is ONLY same-owner unbound private_attachment: expectedRevision exact nonnegative safe integer, operationId exactUUIDv4; close body shape/actor before lookup, then owned lookup. Within one same-session transaction set revokedAt once, null readable pointer, increment asset revision and write revoke audit with operation ID. Same operation replay returns200 `{success:true,data:{assetId,revoked:true,revision}}` from its immutable recorded result after identity comparison; stale new operation409. No file/version delete, owner reassignment or promotion. Clinical detach, clinical revoke/retention holds and public withdrawal are EXCLUDED until their real policy/actor bindings freeze; internal calls return503 DOCUMENT_POLICY_UNAVAILABLE. The full S1 later replaces physical BookingDocumentService deletion with authorized reference-detach/retention, without using this unbound-only command as clinical deletion authority.

## Implementable Node filesystem algorithm and explicit threat boundary

Use a single configured upload root (the existing CONFIG-resolved root) and reserved child `__private_assets_v1`, owned by the service OS uid, root/private-directory0700 and files0600. Root is provisioned/configured by the local/deployment operator, not supplied by the HTTP request. The threat boundary excludes a malicious same-uid process/administrator capable of replacing that root or mutating held inode contents: Node's path APIs do not provide a portable openat2 directory-descriptor containment primitive. Do NOT claim lstat+O_NOFOLLOW defeats an adversary replacing arbitrary ancestors concurrently. A deployable root requires restrictive parent permissions and exclusive application ownership; multi-host/shared-NFS writers are unsupported until separately reviewed. No mkdir/chmod/inventory runs in preparation.

New storage keys use only server-generated lowercase24hex asset/version IDs and32byte randomhex filename; reject any manifest key not matching the fixed grammar. Initialization/admission lstat and realpath the trusted root/reserved child; require actual directories, expected uid/mode, no symlink and record dev/ino. Existing hostile/foreign paths fail503; never adopt/chmod them to make admission pass. Revalidate those identities before each storage operation and after completion; drift fails closed. This detects drift but cannot make stronger guarantees against the excluded hostile same-uid ancestor race.

Creation uses safe generated child directories, mode0700; new files opened `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW`, mode0600. fstat verifies regular/nlink1/uid/mode and holds that fd while streaming bounded input, hashing/counting actual bytes, fsyncing and closing. Reopen read-only/no-follow under the same root identity, verify full bytes/hash/size and file identity before metadata publication. Never write existing keys, follow client symlinks, reuse a parser path as a final key or adopt an existing file on EEXIST. Failed capture remains an unreachable owned orphan, never an attached available document.

For content read, after metadata/state/audit admission, open the fixed storage key read-only O_NOFOLLOW; fstat require regular/nlink1/owner/mode/size. FIRST pass over that HELD descriptor computes full SHA256 and bytecount using bounded64KiB reads, validating declared media type and immutable metadata; fstat before/after hashing must match dev/ino/size/mtime/ctime. No response body bytes before this check. SECOND pass streams the SAME descriptor from position0 using explicit positions/chunk bounds, max10MiB,30s deadline/disconnect cleanup; verify descriptor identity again at end. Root/manifest/file mismatch503 before first byte, or terminate connection and retain failed audit if discovered after transmission. Do not silently reopen by path after verification. Auth admission and inode checks cannot revoke already transmitted bytes or defeat the excluded hostile same-uid in-place write during the second pass; immutable permissions and sole-writer behavior are deployment assumptions, honestly measured in fixtures.

Minimal existing-path isolation is required before NEW private files can exist: FileController's common static/fetch/structured/info resolver rejects any canonical path within the reserved subtree BEFORE existence/stat/read, including alternate encodings and normalized aliases. Never rely on obscurity or extension. FileService generic upload accepts only a flat `[A-Za-z0-9_-]{1,64}` module other than reserved subtree and an optional exact24hex recordId before filesystem work; any unsupported old caller is a visible compatibility failure, not path escape permission. deleteFile similarly admits only canonical contained legacy paths, forbids the reserved subtree and symlinks/outside-root resolutions, and cannot erase new private files. Existing public-image return fields/URL generation and ordinary allowed-module writes stay unchanged. The trusted-root boundary applies to these legacy isolation checks too; tests must verify no remote request can create/replace the reserved ancestors through old module/record inputs.
