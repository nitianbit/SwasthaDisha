# Private clinical documents and explicit public images — draft contract

13 November 2026. Author: internal Codex `/root/lab_remaining_audit`. PREPARATION ONLY; no self-approval. Two actual independent nonauthor Standards/Spec contract decisions precede source edits. This draft defines the next shared customer/lab document milestone; source candidacy, actual focused execution, compatibility/client cutover and clinical/release acceptance remain distinct.

## Problem, reuse and selected scope

The owner confirms images intended for publication are public. A report can also be a JPEG/PNG, and a client can set an arbitrary profilePictureUrl/imageUrl; neither extension, image MIME nor an arbitrary URL reference proves publication authority. Existing `/api/static/*` directly serves the entire upload root. The authenticated `/api/v1/file/static/*` and `/fetch?url=...` ultimately use the same pathname reader. Authentication alone therefore does not establish resource authority. Generic upload chooses module/recordId before formidable parsing and can write caller-shaped directories. Provider diagnostics persistence uses stable callback filenames and can overwrite prior bytes. Booking document deletion physically deletes files. All are actual source facts, not a claim about which bytes exist in production.

Reuse the existing file module, booking/external-booking repositories, AppError, authenticated router, formidable and provider adapters. Extend the file module with narrow authoritative asset/version metadata and private storage; do not add a generic workflow engine, duplicated clinical service or blanket authorization framework. Root owns integration. Customer contact work, unrelated services, dependencies/lockfiles, startup, keys and provider accounts remain untouched.

Selected implementation mechanics: authoritative asset purpose and owner links; fresh owned uploads; authorized actual-byte reads; immutable version persistence; explicit public-image publication; compatibility resolution for legacy paths; bounded provider acquisition. New qualified prescription approval, clinical signatory/release, new caregiver consent, lab staff onboarding and full provider callback authenticity are separate contracts. They cannot be inferred from this document's storage mechanics.

## Authoritative asset and version metadata

Add a focused collection `FileAsset` in the existing file module, not an independent domain service. Every new asset ID/version ID is server-generated ObjectId; callers cannot select either ID, a disk key, checksum, uploader, purpose, owner, source authenticity, release state or current-version pointer. External IDs are provenance, never global document IDs.

Asset fields: schemaVersion1; immutable purpose `clinical_document|private_attachment|public_image`; owner principal type/ID; resource kind/ID or explicit unbound upload; patient/account reference only when derived from the current trusted resource; create actor/time; current readable version ID; revokedAt; revision. Clinical resource kinds initially `booking|external_booking`; supplied pharmacy/business/corporate IDs do not substitute for trusted ownership. Unbound private uploads are visible only to their uploader and cannot be made public by changing a profile URL.

Each immutable `FileAssetVersion` records assetId, server versionId, opaque private key, SHA-256, actual byte count, actual detected media type, capturedAt, source `owned_upload|labstack|healthians|legacy_import`, source document/reference, acquisition state, completeness `preliminary|final|unknown`, validation `quarantined|validated|rejected`, clinical publication `unreleased|released|legacy_access_unknown`, amendsVersionId/reason where applicable, and immutable actor/provenance. Provider strings are observations; no unverified callback sets authenticated=true, final=true or clinically verified. `legacy_access_unknown` is available only to the separately authorized migration bridge preserving an established existing access association, never an arbitrary upload/request parameter.

Use two small metadata models/repositories within the file module; no embedded unbounded version array. Define create-only correctness indexes for version identity `(assetId, source, sourceDocumentReference, contentSha256, completeness, sourceVersionLabel)` with all components explicitly normalized to bounded strings, and `(assetId, versionId)`. Equivalent bytes with different observed completeness/provenance may be a different version; identical identity retries reuse the existing version after comparing all immutable fields. Required index creation/readiness follows existing F13/C2 gates; no startup syncIndexes, duplicate deletion or claim that a declared schema index is installed. Writers fail503 `DOCUMENT_STORAGE_UNAVAILABLE` when required index readiness is absent. Preserve missing/unknown labels explicitly rather than fabricate provider version information.

Private disk storage is a generated `.clinical-assets/<assetId>/<versionId>/<random-key>` subtree beneath the configured upload root; URLs never expose it. File creation is exclusive with `wx`, mode0600 in mode0700 owned directories; no raw resource/user filename becomes a disk path. An existing file/key is never overwritten. Validate root and path components using lstat/no-follow and descriptor checks; reject symlinks/hard-link adoption, path traversal, NUL, separators and root drift. These checks and descriptor-based streaming must be reviewed against the actual admitted runtime; path.resolve-prefix alone is insufficient. No operational storage path is read during preparation.

Persist bytes first, close/verify their descriptor length/hash, then insert immutable version metadata and conditionally advance a metadata pointer with the expected asset revision and authoritative resource scope. Never expose bytes until a committed authorized pointer/state references them. Filesystem and Mongo are not one atomic transaction: failed metadata writes may leave private unreachable orphans. Record the failure; cleanup is a separately owned retention operation, never broad unlink/prune. Duplicate identity losers use the existing metadata/version after verifying identity; their private orphan stays unreachable pending owned cleanup. Metadata must never advertise a missing/incomplete object as readable. Reference detach/revoke does not physically erase historical clinical bytes.

## Commands, access and errors

All routes preserve existing authenticate precedence where mounted under `/api/v1/file`. New routes: `POST /api/v1/file/clinical/:resourceKind/:resourceId/uploads`; `GET /api/v1/file/assets/:assetId/versions/:versionId/content`; `GET /api/v1/file/assets/:assetId/versions`; and `POST /api/v1/file/public-images/:resourceKind/:resourceId/uploads`. Parameters are primitive bounded strings, IDs exact24hex without coercion. Validate route/body shape before lookup; body may not supply protected metadata or absolute/storage URLs. Invalid syntax400 `DOCUMENT_INPUT_INVALID`; unauthenticated401 remains existing middleware behavior. Missing and foreign private assets both404 `DOCUMENT_NOT_FOUND`, before opening any byte descriptor or provider call. Missing index/storage readiness503 `DOCUMENT_STORAGE_UNAVAILABLE`; pointer/revision conflict409 `DOCUMENT_VERSION_CONFLICT`; quarantined/not-released reader503 `DOCUMENT_NOT_AVAILABLE`. Responses omit absolute paths, raw provider payloads, signed provider URLs, private hashes as access tokens and patient information unnecessary to the call.

Owned-resource clinical commands require an exact current trusted row and exact resource scope before multipart parsing or provider acquisition. For `user`, require scalar stored booking.userId/externalBooking.userId equal the signed account, not req.body/query owner, phone/email match or dependent ID alone. Admin reads retain an explicit reviewed current admin boundary, with access audit; an admin label never becomes a clinician/signatory. HR/corporate/pharmacy linkage is not chart-read authority. Specialist/lab staff access is closed until a trusted current staff identity, branch/assignment and purpose/consent contract can be resolved; do not infer it from a role string, same corporateId or a specialistId string alone. Existing legitimate specialist/client paths are a compatibility gate, not silently granted universal access. New caregiver access remains closed without its independent consent/authority contract.

For a version read, fetch the current asset and authoritative booking linkage on every request, enforce its exact permitted recipient/state, verify the selected version belongs to that asset and resource, then open/validate/stream the stored descriptor. Never accept an asset owned by another person merely because its URL was copied into the caller's booking/profile. Resource-bound legacy paths additionally require their canonical path resource ID to match the trusted resource and exact approved stored reference; copying another booking's path into one's own row cannot grant access. Unbound `general/...` and remote references lack this provenance and remain denied until separately classified/imported. No user-supplied URL is fetched as a download proxy.

Private metadata and bytes, including errors and HEAD responses, use `Cache-Control: private, no-store`, `Pragma: no-cache`, `Vary: Authorization`, `X-Content-Type-Options: nosniff`. Use validated Content-Type and safe attachment filename; do not expose 304/public ETag/Last-Modified paths or redirects to a public object. Reject Range initially with416 rather than bypass authorization or implement unreviewed partial hashing. Streams use descriptor identity, bounded bytes and disconnect cleanup; no synchronous whole-file read. Log minimal actor/resource/version/outcome/correlation only; access logs contain no bytes, signed URLs or patient payloads. Already downloaded or previously publicly cached bytes cannot be revoked by this fix.

## Genuine public images and existing URL compatibility

Public-image publication is an explicit server-authorized purpose with fresh uploaded bytes, not a derived property of a profile/image URL. Initially permit only exact user-owned profile resource, operational owning-pharmacy profile, and administrator-controlled shared catalogue image resources after the actual writer bindings are frozen. Other public resource kinds require their own reviewed writer mapping. Public publication accepts fresh validated raster JPEG/PNG/WebP only, never a URL, existing private asset ID, SVG/HTML/PDF or generic file path. Do not promote/copy a private asset through this command. Possession of bytes is not clinical approval; this command supplies no prescription/report semantics.

The public route may serve only an authoritative `purpose=public_image` published asset/version or a separately approved legacy public-image registry entry. Its public cache applies only there. Private/clinical purposes always win over a conflicting legacy classification. Preserve the existing image response fields and renderable URLs through compatibility adapters; do not rewrite unrelated remote image URLs or infer that their contents are safe to proxy.

All aliases `/api/static/*`, `/api/v1/file/static/*`, `/fetch`, and any future structured/info route dispatch through this same purpose/access decision. They never fall back to arbitrary filesystem access on lookup failure. Old clinical URLs resolve to the authenticated gateway using exact resource-bound migration/reference metadata, without public Location redirects; an unauthenticated caller receives no bytes. `/fetch?url=` admits only canonical local aliases, not full URLs/schemes/backslashes/double decoding/query-fragment path tricks.

Legacy public-image registry entries contain exact canonical relative path, content SHA-256, actual image type/size, publication resource and explicit review provenance. They are deployment data produced from an authorized inventory, not inferred from extension, directory name or the current value of an arbitrary profile field. A changed file/hash or missing classification fails closed404. Actual legacy paths and supported clients are not supplied by the current source; Root owns the subsequent compatibility/cutover decision. Source-ready new assets/authorized uploads/private versions may be implemented independently, but the complete static-route cutover cannot be called compatible until approved public-image fixtures and intended clients succeed. Never leave the arbitrary gateway open permanently and call privacy complete.

Generic legacy upload endpoints remain response-shape compatible but create unbound private assets by default; a caller-shaped module/recordId does not authorize clinical binding/publication. Context-specific reviewed adapters may bind an owned clinical resource or explicit public-image resource before parsing. Reject path-shaped module/recordId before directory/file activity; do not keep the old module path construction as a fallback. Existing client publication flows require mapping to the explicit server-authorized public-image command. Old BookingDocumentService filename/MIME guesses may remain presentation labels only; they never select privacy or clinical release.

## Upload, acquisition, validation and version rules

Retain the existing10MiB per-file ceiling; enforce at most5 files and20MiB total per request, bounded fields and filenames, actual streamed sizes and request timeout before persistent promotion. Allow detected PDF/JPEG/PNG/WebP; reject declaration/content mismatch and unknown/application-octet-stream with415 `DOCUMENT_MEDIA_UNSUPPORTED`; too large413 `DOCUMENT_TOO_LARGE`. A type check is not a malware scan. New clinical uploads enter quarantined/unreleased, with the actual scanner state recorded. No scanner success may be fabricated; until a separately admitted scanner/validator and permitted release contract are configured, reader returns503 for these new quarantined versions. Existing legacy association may be imported as history/access unknown only by the accountable bridge, not by relabeling new uploads. Public image validation/publication is separate from clinical scanning/signatory approval.

Provider diagnostics persistence replaces stable filenames in both explicit report fetch and delivered-webhook paths. Reuse existing adapter order/report retrieval, but receive bytes only through a bounded acquired-result port tied to the trusted local order/integration/external order/report ID. Store immutable versions; duplicate same identity reuses metadata, different hash/completeness/provenance appends. A correction requires an explicit source correction observation/reason when available; otherwise source relationship is unknown, never invent amendsVersionId or finalness. Existing arrays become compatible gateway handles to exact versions; retain prior handles/history rather than replacing the only copy. Never set clinically verified/released merely because `status=report_delivered` or a download succeeded.

Existing permitted legacy reads are preserved through a source-bound migration/access bridge recording current approved recipients, legacy provenance and history unknown; this is not new clinical verification. Newly introduced staff/release/publication behavior stays closed pending qualified policy. New data acquisition is not a shortcut around that gate. The current unauthenticated webhook remains a separate security defect: unverified events may not create released/available versions or new public URLs under this milestone.

Provider outbound report fetching is affected: current Healthians download accepts arbitrary URLs and redirects, LabStack fetch buffers without an explicit report ceiling. Freeze provider-specific HTTPS hostname/path/port contracts before enabling download. Reject credentials, non443 ports unless specifically reviewed, nonHTTPS, private/loopback/link-local/reserved/metadata addresses, unexpected DNS answers and redirects. Initial policy `maxRedirects:0`, no ambient proxy,10MiB streamed limit and20s deadline; bind validated resolution to connection and TLS hostname verification, avoiding validation-to-connect DNS races. Unsupported provider destinations return503 `DOCUMENT_SOURCE_UNAVAILABLE`; unsafe syntax/destination is502 `DOCUMENT_SOURCE_REJECTED`. Never guess a Healthians signed-report CDN host from HEALTHIANS_BASE_URL. If genuine provider redirects/CDN addresses are required, their exact approved host/redirect/resolution contract must be separately frozen before use. Read operations serve persisted artifacts; they do not become unrestricted synchronous HTTP proxies. No provider calls are authorized by this draft.

## Required focused evidence

Two actual independent contract decisions precede implementation. Exact source freezes and two actual nonauthor source/composition decisions precede activation. Actual focused checks require complete pre-import C3 and the applicable correctness-index/storage profile; no legacy suite, current app import or test smoke is admitted here.

1. Anonymous/foreign/malformed access to the same clinical PDF and JPEG yields no bytes across all aliases, metadata, HEAD, cache and URL-copy paths; same signed owner succeeds for an admitted readable version. A copied foreign URL in one's own booking/avatar cannot authorize it. Wrong stored scalar ownership/asset-resource/version combinations fail closed before disk/provider activity; measured query/open counters establish that boundary.
2. Explicit published image and approved legacy image render anonymously with unchanged required URL/response shape. Clinical JPEG remains private; unpublished image, mismatched registry hash, arbitrary profileURL promotion, SVG/HTML and clinical-image path masquerade never become public. Measure existing mobile/web image-flow compatibility separately from synthetic fixtures.
3. Same resource/report identity repeated preserves one immutable version; changed bytes/completeness/provenance preserve both with correct links. Equal filenames/report IDs under other users/orders/integrations cannot collide. Retry/crash between exclusive file write/metadata insert/pointer change never overwrites originals or exposes incomplete/orphan bytes. Real unique indexes and CAS/readback evidence are required; source hash checks alone are not idempotency proof.
4. Quarantine/rejected/unreleased/revoked assets deny. Uploader cannot claim verified/final/released/source authenticity. New generic/private upload cannot be republished through imageURL, generic update, file alias or forged manifest. Detach/delete preserves retained clinical history and records authorization; no synchronous physical deletion.
5. Traversal, encoded separators, NUL, symlink/hard-link/root replacement and file-swap races deny without outside-root reads/writes. Stream disconnect cleans owned descriptors only; errors are sanitized and no private cache headers/304 leak bytes. Overlimit and malformed multipart cases leave no published/attached partial files.
6. Stubbed HTTPS provider tests exercise allowlisted destination, unsafe DNS/IP, redirects, oversized/chunked/decompression bodies, timeout, MIME mismatch and unknown CDN gate. No live provider needed for these focused checks; actual provider acceptance remains separate.
7. Actual-source controls restoring arbitrary static fallback/public cache, allowing an arbitrary profileURL publication, omitting owner/resource/version scope, using overwrite writes, bypassing quarantine, or removing destination/byte controls must fail their corresponding behavioral assertion. Record exact runtime/source bindings; retain failed/NOT_RUN evidence honestly.
