## C3 disposable ownership before integration execution

Before any imports/startup can connect or trigger effects, a bootstrap must establish test ownership and sanitized configuration:

- Start or create an explicitly disposable fixture under the harness, such as a dedicated local MongoDB replica-set container/process. Record its run ID, resource identity, namespace and cleanup scope. A supplied URI, a database name containing test or an externally added marker alone is insufficient proof of ownership.
- Derive the fixture connection from that resource; reject ambient/operational URIs, remote Docker context or shared DB overrides unless explicitly authorized and proven disposable. Validate ownership/allowlisted destination and test role before connecting. The example name latest must be denied when it is not harness-owned.
- Give the test child a sanitized environment/workspace and explicit fixture paths. Exclude ordinary .env, real credentials, sensitive tracked artifacts and real provider clients. Prepare provider stubs and filesystem/output limits before dynamic application imports; prohibit application startup from silently loading operational fallbacks.
- Exercise preflight denial through pure fake connectors: unknown/mismatched resource, forged run metadata, operational env and disallowed host must produce failure with zero DB/provider connection attempts and zero writes. Separately verify a valid harness-created fixture path.
- Only after preflight may transaction tests import/run. Cleanup/index setup can affect only the owned fixture, with explicit evidence and bounded teardown; never drop/rebuild an arbitrary configured database. Required suites must not silently pass with zero assertions or all cases skipped.
