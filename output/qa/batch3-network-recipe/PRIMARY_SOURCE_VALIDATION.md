# Primary-source check for the network rule

10 November 2026. Internal Codex nonauthor read-only review of integration `eba7e5c`. Public source/documentation was read; no local socket, daemon, container, sysctl, network namespace or application was inspected. These references support semantics; they do not attest the deployed/desktop kernel or explain the actual historical failure conclusively.

- Linux v6.12 [if.h](https://raw.githubusercontent.com/torvalds/linux/v6.12/include/uapi/linux/if.h) defines the IFF bits used, and [if_arp.h](https://raw.githubusercontent.com/torvalds/linux/v6.12/include/uapi/linux/if_arp.h) defines loopback type 772. The reviewed constants match.
- Linux v6.12 [net-sysfs.c](https://raw.githubusercontent.com/torvalds/linux/v6.12/net/core/net-sysfs.c) reads the stored device flags for sysfs and reports `down` when the device is not running. [Operational-state documentation](https://docs.kernel.org/networking/operstates.html) distinguishes administrative state from operational state and describes DOWN as unable to transfer normal data. The new rule requires both IFF_UP clear and operational down for non-loopback devices; an unknown/up active device is not excused by a name.
- Linux [capabilities(7)](https://man7.org/linux/man-pages/man7/capabilities.7.html) assigns interface/routing administration to CAP_NET_ADMIN and raw/packet sockets to CAP_NET_RAW. The unchanged controller requires UID/GID 1000, capability drop ALL, no added capabilities/privilege/devices and no-new-privileges. The conclusion that reviewed code cannot raise an admitted down device relies on the already stated trusted-host/runtime model, not a fresh effective-capability measurement.
- Pinned Node v22.23.4 [libuv linux.c](https://raw.githubusercontent.com/nodejs/node/v22.23.4/deps/uv/src/unix/linux.c), `uv__ifaddr_exclude` around line 1832, excludes entries lacking UP/RUNNING or an address. Its result therefore cannot establish the absence of retained addresses on down devices; the sysfs rule and parent isolation checks remain necessary.
- Kernel [fallback-tunnel sysctl documentation](https://docs.kernel.org/admin-guide/sysctl/net.html#fb-tunnels-only-for-init-net) describes automatic fallback-tunnel creation in new namespaces. That is a possible explanation for the sampled extra names, not proof of the local sysctl value, kernel build or namespace origin. No sysctl read/grant is added.
- Linux v6.12 [tcp_ipv4.c](https://raw.githubusercontent.com/torvalds/linux/v6.12/net/ipv4/tcp_ipv4.c), `tcp_v4_err`, propagates received unreachable errors during connection setup; [icmp.c](https://raw.githubusercontent.com/torvalds/linux/v6.12/net/ipv4/icmp.c) maps network-unreachable ICMP to ENETUNREACH. A rejected canary with that code alone does not prove no packet left or enumerate IPv4/IPv6 routes.
- [Docker none driver documentation](https://docs.docker.com/engine/network/drivers/none/) describes network-stack isolation with only loopback created by Docker. The fixed controller checks NetworkMode none and the parent isolation fields; it does not independently attest namespace provenance. The kernel can separately create fallback devices.

No production reachability, deployment revision, runtime C3 acceptance or recovery guarantee follows from this source research. Preserve the recorded historical failures and require the exact future run review. This note updates the basis previously labelled memory-only; it does not retroactively convert earlier records into new measurements.
